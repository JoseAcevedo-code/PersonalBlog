Keep this post around. It's not really for readers — it's a rendering test. Every
element the site styles appears below, so when I change the CSS I can load this
page and see immediately what I broke.

## Frontmatter

Every post starts with a block of frontmatter. Only three fields are required:

```yaml
---
title: 'Post title'
description: 'One sentence. Shows up in the index and in link previews.'
pubDate: 2026-08-18
tags: ['optional', 'array']
updatedDate: 2026-08-19  # optional
draft: false             # optional, defaults to false
---
```

If a required field is missing, the build fails with a message naming the file
and the field. That's deliberate — a post with no description looks broken in
the index and in every social preview, so it's better to catch it at build time.

### Drafts

Setting `draft: true` keeps a post out of the production build, the RSS feed,
and the sitemap. It still renders in `npm run dev`, tagged with a small badge,
so I can preview work in progress.

## Text

Regular paragraph text sets in Karla at a comfortable measure — around 34rem,
which lands near 70 characters per line. You get **bold**, *italic*, `inline
code`, and [links](https://astro.build) that underline in moss.

> Block quotes sit behind a moss rule and set in italic.

## Lists

Unordered lists use a short dash instead of a bullet, which echoes the hairlines
used elsewhere:

- First item
- Second item, which runs long enough to wrap onto a second line so I can check
  that the hanging indent lines up the way it should
- Third item

Ordered lists keep their numerals, since the number carries meaning:

1. Clone the repo
2. Install dependencies
3. Start the dev server

## Code

Fenced blocks get syntax highlighting from Shiki, with separate light and dark
themes that swap with the site theme:

```ts
type Post = {
  title: string;
  pubDate: Date;
  tags: string[];
};

function recent(posts: Post[], limit = 5): Post[] {
  return [...posts]
    .sort((a, b) => b.pubDate.valueOf() - a.pubDate.valueOf())
    .slice(0, limit);
}
```

Long lines wrap rather than scrolling horizontally, which I find easier to read
on a phone than a scrollbar inside a scrollbar.

## Images

Images get a soft border and rounded corners. Put them in `src/assets/` and
import them for automatic optimization, or drop them in `public/` and reference
them by path if you don't need resizing.

## MDX

This file is `.mdx` rather than `.md`, which means it can import and render
components inline. Plain `.md` works fine for most posts — reach for MDX only
when a post actually needs something interactive.
